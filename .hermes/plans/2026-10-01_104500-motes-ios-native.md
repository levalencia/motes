# Motes iOS — Native SwiftUI App Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build a native iOS app that mirrors the Motes web UI, consuming the backend API over Tailscale.

**Architecture:** SwiftUI + async/await + URLSession + WebSocket. MVVM pattern. API client layer talks to `http://<tailscale-ip>:8001`. Same features as web: chat, voice calls, services, proactive notifications.

**Tech Stack:** SwiftUI (iOS 27), Swift Concurrency (async/await), URLSession, AVFoundation (audio), WebSocket (URLSessionWebSocketTask), SSE (EventSource), Keychain (token storage)

## Configuration

```swift
// Config.swift
enum Config {
    // User sets this once — their Tailscale Motes server
    static var baseURL: String {
        UserDefaults.standard.string(forKey: "motes_server_url") 
            ?? "http://localhost:8001"
    }
}
```

First launch: user enters their Tailscale URL (e.g., `http://motes-server:8001`).
Saved in UserDefaults. All API calls go through this.

## Key Decisions

1. **No WebView** — pure SwiftUI, native controls
2. **Tailscale URL** — user configures once, stored in UserDefaults
3. **Keychain** — JWT token stored securely, not UserDefaults
4. **AVAudioEngine** — native audio capture, far superior to browser
5. **SSE** — URLSession bytes for chat streaming + proactive events
6. **WebSocket** — URLSessionWebSocketTask for voice calls
7. **MVVM** — ViewModels as @Observable classes
8. **iOS 27** — latest APIs, no backward compat needed

## Risks

- **Audio format**: Server expects webm, iOS records in PCM/AAC. May need to send raw PCM and have server handle it, or add a server endpoint that accepts PCM directly.
- **SSE parsing**: No built-in SSE client in iOS. Need manual line-by-line parsing of `data:` events from URLSession byte stream.
- **Background SSE**: iOS kills background connections. Proactive notifications may need push notifications (APNs) for reliability when app is backgrounded.
